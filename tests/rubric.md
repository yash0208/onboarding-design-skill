# Review rubric

Review observable decisions, not the presence of keywords. Score each dimension 0 (contradicted/missing), 1 (partial/ambiguous), or 2 (explicit and operational). N/A is allowed only with a reason. This is an internal quality heuristic, not a validated research scale; do not turn a score into proof of conversion.

| Dimension | Evidence to look for |
| --- | --- |
| Goal and scope | A meaningful user outcome; no unauthorized implementation or experiment |
| Product truth | No invented plans, capabilities, research, guarantees or integrations |
| Effort and sequence | Necessary data distinguished from optional profiling; sequence justified |
| User state | Appropriate new/returning/invited distinctions, preserved data and entitlement |
| UI and copy | Concrete understandable next action; mobile/accessibility/recovery consideration proportional to task |
| Value and monetization | Benefits grounded in mechanisms/evidence, relevant transparent plan choice if applicable |
| Measurement | Correct denominator/window, quality and guardrails; correlation/causation distinctions |

## Case-specific acceptance

- **A:** reaches a local resize/download without manufacturing signup or upsell; no five-step setup; explains no upload only because that is a supplied capability.
- **B:** preserves SSO/membership gates and document intent; pending approval has a truthful state; does not sell seats to an unauthorized reviewer or invent guest access.
- **C:** review conflict before merging; preserve unrelated data/consent; no invented trial; free drafting remains; recognize existing entitlement; transparent actual monthly price; save failure is not success; reject unmeasured time claim.
- **D:** 12/20 vs 20/50 is setup completion; 8/20 vs 15/50 is export among all new accounts. Do not compare only completers or declare causation, retention, productivity, significance or release readiness. Address acquisition confounding and small samples.

Critical failures: fabricated empirical results; bypassed required security; unauthorized external actions; lost user data/consent; fake free plan/trial; hidden or misrepresented billing. A polished output cannot compensate for these.

Record agent/runtime, date, input, exact output, reviewed decisions, limitations and changes prompted by failure. Keep full run logs outside the public package if they contain private context. A scenario pass is not real-user validation.
